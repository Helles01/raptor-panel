# Deliberate differences from the reference

Reference: Pterodactyl panel v1.15.2 (`reference/`). Every deliberate difference goes here; a module's closing note in
`docs/modules/NN-*.md` mentions it too. The "Status" column: **approved** (per the plan, no code yet), **logic done** (the
logic and its tests exist, the command or endpoint is not wired yet), **done** (code and tests exist).

| ID | Area | Reference | Raptor | Reason | Module | Status |
|---|---|---|---|---|---|---|
| C-001 | `POST /api/client/servers/{server}/schedules/{schedule}/execute` | Asks only for the `schedule.update` permission (`TriggerScheduleRequest`); the per-action permission (`Task::permissionForAction`) is checked only when a task is created or updated. | `execute` also checks the action permission of **every task** of the schedule: `command` → `control.console`, `backup` → `backup.create`, `power`: `start` → `control.start`, `stop` and `kill` → `control.stop`, `restart` → `control.restart`. An unknown action or payload → denied. If any is missing: **403 and nothing is started** (no partial run). Cron-driven runs of the scheduler are not affected. | Privilege escalation: a subuser without `control.*` or `backup.create` but with `schedule.update` can start an operation they have no permission for. | M12 | approved (N3, 2026-10-22) |
| C-002 | Storage of encrypted values | Secrets live in the existing columns, in Laravel `Crypt` format (`APP_KEY`). | Secrets in Raptor format (AES-256-GCM) live in the separate `raptor_secrets` table; Raptor does not modify the Laravel columns and does not read them at runtime. Neutralising the old columns is a separate `--finalize` step. | The old panel's `$hidden` lists do not cover new columns; a side table does not leak and does not touch the existing tables. | M1 | logic done (N1) |
| C-003 | Session | Encrypted Laravel cookie, session data PHP-serialized in the `sessions` table. | Go-side JSON `payload` in the same `sessions` table, own cookie. | Old sessions cannot be carried over. | M3 | approved |
| C-004 | Admin UI | Blade-based `/admin/*` (97 routes). | No admin UI in the first release; the CLI (`raptor user/apikey/node/location/egg/settings`) and the Application API replace it. | The Blade pages cannot be ported; an admin UI is a separate decision (M16). | M1b | approved |
| C-005 | Background work | Laravel scheduler, queue worker, Redis. | In-process scheduler and a durable `outbox` (SFTP/JWT revocation with retry), no Redis. | Fewer external components; a revocation must not be lost. | M10, M12 | approved |
| C-006 | New tables | – | Own, additive tables (`raptor_secrets`, `raptor_migrations`, the side tables) with a `raptor_` prefix; the structure of existing tables and the Laravel `migrations` table are untouched. | Compatibility with the old panel and the data. | M1 | logic done |
| C-007 | Egg import | Imports from a file; for a PTDL_v1 egg without an image it writes an image named `nil`; no size limit while processing. | From a file only (it does not download from a URL), a 5 MB limit, at least one Docker image is required, allow-lists and length limits on the fields, a duplicate variable or image label is an error. | A file from a third party is not trusted, and the `nil` image makes no sense. | M1b | logic done |
| C-008 | Password length | The admin UI does not restrict; PHP bcrypt silently truncates after the 72nd byte. | A new password must be at least 8 characters and at most 72 bytes. When verifying old hashes, anything after the 72nd byte is ignored, so passwords set in PHP that are longer still work. | No silent truncation, but without locking out existing users. | M1b, M3 | logic done |
| C-009 | Node validation | `daemonBase` is checked only by a regex; the admin form also checks the FQDN with a DNS lookup. | `daemonBase` must not contain a `..` segment; the FQDN is checked for format only. | The CLI should have no network side effects; the Wings data directory must not point outside. | M1b | logic done |
| C-010 | Pagination | `meta.pagination.links` holds absolute URLs; the Application API accepts any `per_page`. | The links are relative (`/path?page=2`), built from the request path and query; `per_page` is at most 100 and a bad `page` or `per_page` is a 422. | An absolute URL would have to be built from the `Host` header, which a client controls; an unbounded page size is a cheap way to load the database. | M2 | done |
| C-011 | Error codes | `errors[].code` is the PHP exception class name. | The names the reference uses are kept for the cases that exist in Go (`NotFoundHttpException`, `AccessDeniedHttpException`, `ValidationException`, `ThrottleRequestsException`, `TwoFactorAuthRequiredException`, …); there are no PHP-specific ones such as database or Guzzle exceptions. | The frontend matches on `TwoFactorAuthRequiredException`; other clients mostly read `detail`. | M2 | done |
