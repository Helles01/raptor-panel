# Deliberate differences from the reference

Reference: Pterodactyl panel v1.15.2 (`reference/`). Every deliberate difference goes here; a module's closing note in
`docs/modules/NN-*.md` mentions it too. The "Status" column: **approved** (per the plan, no code yet), **logic done** (the
logic and its tests exist, the command or endpoint is not wired yet), **done** (code and tests exist).

| ID | Area | Reference | Raptor | Reason | Module | Status |

| C-001 | `POST /api/client/servers/{server}/schedules/{schedule}/execute` | Asks only for the `schedule.update` permission (`TriggerScheduleRequest`); the per-action permission (`Task::permissionForAction`) is checked only when a task is created or updated. | `execute` also checks the action permission of **every task** of the schedule: `command` → `control.console`, `backup` → `backup.create`, `power`: `start` → `control.start`, `stop` and `kill` → `control.stop`, `restart` → `control.restart`. | C-022 | Cron expressions of schedules | Any text is passed to `dragonmantank/cron-expression` v3.6.0; what it throws on is "does not evaluate to a valid expression". It also accepts forms with a quirky meaning: a step as large as or larger than the field (`*/60` in the minute means minute 0 only), a descending range in a list (it matches nothing), numbers such as `+5` or `1e1`, `1-5W`, `*W`, and in the day of week a numbering that is chosen by looking for the character 7 in the text (so `MON-SUN` can skip Sunday). | Each field is checked against an allow-list (letters, digits and `*,/-#?`, at most 255 characters). Refused with the same error text: the quirky forms above. 0 and 7 are always Sunday. When both day fields are given a day matches if either does (as in the reference). Schedules already stored with such a form are found by the audit before cutover (M17), not at their run time. | M12 | logic done |
| C-023 | Task of an unknown action | `Task::permissionForAction` returns null for an unknown action or power signal, and the authorisation then passes. | An unknown action or signal has no permission: it is refused, and a schedule that contains one cannot be run by hand (`schedules.CanRun`). | Fail closed; the allow-lists of the task rules reject such tasks on input anyway, so this only matters for stored rows.
